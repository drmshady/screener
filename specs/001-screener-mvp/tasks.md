# Tasks: US Stock Screener MVP

**Input**: Design documents from [E:\screener\specs\001-screener-mvp\](.)
**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md), [data-model.md](data-model.md), [contracts/openapi.yaml](contracts/openapi.yaml), [quickstart.md](quickstart.md)

**Tests**: Constitutionally required, not optional. Constitution IV mandates golden-fixture tests for every indicator BEFORE any strategy depends on it. Constitution III mandates deterministic backtests for every strategy enabled by default. Constitution V mandates a no-directive-copy lint and a disclaimer-everywhere check in the frontend. These tests appear in the task list as required work, not as optional add-ons.

**Organization**: Tasks are grouped by user story to enable independent implementation and testing of each story. Within each story phase, tests precede implementation where the constitution requires it.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies on incomplete tasks)
- **[Story]**: Which user story this task belongs to (US1–US6)
- Each task includes the exact file path it touches.

## Phase 10: Data caching & incremental ingest (yfinance rate-limit mitigation, added 2026-06-10)

**Problem**: the live screen currently re-fetches from yfinance on every run. `build_universe_snapshot` only fetches prices for tickers **entirely missing** from the Parquet store (so already-stored tickers go stale and are never refreshed), and `_ticker_profiles` re-downloads `.info` + `balance_sheet` for **every** liquid ticker on **every** run (the biggest rate-limit risk). Goal: persist fetched data and fetch **only new/stale data** incrementally.

**Bug to fix first**: `save_prices` ([backend/src/data/prices_store.py](backend/src/data/prices_store.py)) uses `existing_data_behavior="delete_matching"` with `partition_cols=["year"]`, so saving a few tickers' new bars **deletes the entire year partition** for all other tickers. Incremental writes will silently destroy the cache until this is an upsert.

Add a `load_last_dates()` helper returning each ticker's max stored `as_of_date`. Tests for upsert-merge and no-cross-ticker-deletion in [backend/tests/data/test_prices_store.py](backend/tests/data/test_prices_store.py). **Done 2026-06-11.**
- [X] T119 Incremental price fetch in [backend/src/data/prices.py](backend/src/data/prices.py)/engine: for each ticker compute `last_stored = load_last_dates()`; fetch yfinance only for `(last_stored + 1 business day) → today` (full history only when the ticker is absent); skip entirely when `last_stored` is the latest completed trading day. Use batched `yf.download(tickers=[...])` instead of per-ticker calls; add retry+backoff. **Done 2026-06-11:** explicit ticker runs use incremental yfinance fallback; broad default screens use local Stooq when available.
- [X] T120 Profile/fundamentals TTL cache: persist `name, sector, fcf_ttm, debt_to_equity, gross_profit, total_assets, gp_to_assets` per ticker with a `fetched_at` stamp in catalog.db (new `ticker_profile_cache` table or reuse `fundamentals`); on screen-run, read cache and only re-fetch tickers whose cache is missing or older than TTL (default 7 days — fundamentals change quarterly).
