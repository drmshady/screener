## Required deploy mechanics for the sentiment feature

### 1. Dependencies — keep the runtime image slim
`backend/Dockerfile` installs `pyproject.toml [project].dependencies` verbatim (wheel-only, no
compiler). Split deps so `torch` **never** enters the image:

| Dep | Where | Why |
|---|---|---|
| `onnxruntime` | `[project].dependencies` (runtime) | Light CPU inference wheel (~15 MB). |
| `tokenizers` | `[project].dependencies` (runtime) | FinBERT WordPiece tokenizer, no torch. |
| `google-genai` | `[project].dependencies` (runtime) | Optional Gemini narrative (owner's key). |
| `anthropic` | runtime, optional | Only if `LLM_PROVIDER=anthropic`. |
| `torch`, `transformers`, `optimum[onnxruntime]` | **`[project.optional-dependencies].export`** | Used ONCE to export/quantize FinBERT → ONNX. **Never baked** into the runtime image. |

Full `torch` would add ~2 GB and bloat CI; the ONNX INT8 model is ~90–110 MB and runs on CPU on the
HF free tier (16 GB RAM), so it is the required path.

### 2. Bake the FinBERT model like the rest of the snapshot
`backend/data/` is **gitignored** — the snapshot is *generated by the publish chain*, not committed.
So the model is a build-time artifact, not an LFS commit:
1. Add `scripts/export_finbert_onnx.py` (uses the `export` extra) that writes
   `backend/data/finbert_onnx/` (model + tokenizer + config), pinned to a FinBERT **revision** for
   reproducibility. Idempotent (skip if present).
2. Call it in `publish_chain.ps1` **before** the docker build (mirrors `seed_universe.py`), and add
   the `export` extra to the CI `pip install` line in `daily-refresh.yml`.
3. Add one line to `backend/Dockerfile` (mirrors the existing scoped `COPY`s):
   `COPY backend/data/finbert_onnx /app/backend/data/finbert_onnx`
This bakes the model read-only + offline → **no runtime HF Hub fetch** (respects FR-006 / no heavy
in-host ingest). Alternative (not preferred): commit the `.onnx` via Git LFS with a
`!backend/data/finbert_onnx/` gitignore negation.

**Hosted-light fallback:** if the ONNX model is not baked, set `SCREENER_SENTIMENT_SCORER=lexicon`
as an HF Space secret — the image stays byte-identical to today and the deterministic lexicon scores
in-host. FinBERT then runs only locally. This is the recommended **first ship** (zero image risk).

### 3. Secrets — two stores, two purposes
| Secret | GitHub repo secret (build/CI) | HF Space secret (backend runtime) |
|---|---|---|
| `FINNHUB_API_KEY` | already present (daily ingest) | **add** (on-request sentiment) |
| `ALPHAVANTAGE_API_KEY` | optional | **add** |
| `GEMINI_API_KEY` | — | **add** (optional narrative) |
| `ANTHROPIC_API_KEY` | — | add only if `LLM_PROVIDER=anthropic` |

On-request sentiment runs on the **Space**, so its keys must be **Space** secrets — not only GitHub
secrets. All keys are runtime env only; `secret_scan.ps1` (publish-chain gate) still passes because
no key is ever written to a file (api-keys-never-write).

### 4. Captured-report store — runtime-writable, never baked
Write the fingerprint-keyed captured store to **`backend/data/cache/`** (already `.dockerignore`d and
gitignored → excluded from the image, runtime-writable, ephemeral). It must **not** be written under
the read-only baked snapshot dirs (`prices/`, `regime/`, `edgar_cache/`, …), preserving atomic-swap
semantics. Because the report fingerprint includes `snapshot_data_as_of`, the daily factory-rebuild
(new snapshot + fresh ephemeral cache) re-authors reports cleanly; determinism holds within a day /
within a deployment (Decision 6). Cross-rebuild persistence would need HF paid persistent storage —
not required.

### 5. Deploy trigger
The bug fixes + sentiment feature are code (+ a baked model), needing no new trading session — deploy
via the existing **code-only** path: `workflow_dispatch` with `force_rebuild=true` (adds `-SkipGuard`).

## Performance (HF free CPU tier, 16 GB RAM)

FinBERT runs **only** on the on-request `/sentiment/report` path — never during screens, regime,
sizing, or page loads, so the constitution's screen SLAs (p95 ≤ 10 s EOD, ≤ 1.5 s single-ticker) are
untouched.

- **Memory:** ONNX INT8 FinBERT ~100 MB on disk, ~150–250 MB resident — negligible vs 16 GB.
- **Model load:** ~0.5–2 s, **lazy-loaded on first sentiment request** (not at app startup) → boot
  and every other route stay fast. Load once; keep the ORT session in memory.
- **Inference:** ~20–80 ms per short text on CPU; a report batches ~10–40 snippets ⇒ ~0.3–2 s per
  ticker on a cache miss (news fetch + optional LLM prose usually dominate).
- **Cache hits cost ~0** (served from the captured store) → steady-state overhead is near zero.
- **Only real latency:** the first sentiment click after a cold Space (Space wake + model load +
  fetch + inference) — a few seconds, acceptable for an owner-triggered analytical action; show a
  loading state.

**Required knobs:** lazy-load the model; **batch** a report's snippets into one inference call; cap
`onnxruntime` intra-op threads (1–2) so it doesn't contend with the web worker on the 2-vCPU Space.
For literally zero added footprint, `SCREENER_SENTIMENT_SCORER=lexicon` has no model, no load time,
and an unchanged image.
